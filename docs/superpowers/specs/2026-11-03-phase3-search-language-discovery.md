# 第三批：中文自然語言推薦、繁簡切換與每週 GitHub 發現

狀態：使用者已授權按以下順序開發。

## 決定與範圍
1. 自然語言找 Skill：在首頁單獨提供「描述需求」區，用戶輸入完整中文句子，零付費 API，用於搜尋已核對的 Skill。顯示 3–6 個相關項目及推薦原因；未知需求明確說未找到，不捏造；與既有關鍵字搜尋並存。結果是規則排序，不冒充真正 LLM 理解。
2. 簡體／繁體：使用純 JavaScript OpenCC 對中文界面與已核實中文內容提供可切換呈現，保存個人語言偏好；Skill 原始名稱、程式碼、網址、安裝指令不轉換。搜尋支援兩種字體。無網路也能切換。
3. GitHub 來源：不存在「全 GitHub Skills 目錄」，公開 API 搜尋有範圍、速率與驗證限制；新增「候選發現」流水線，週期性透過多個 GitHub repo 搜尋語句發現含 SKILL.md 的 repo 與路徑。候選資料與已審核的 117 個分開；只能在人工補齊中文介紹並核對來源後進入正式目錄。
4. 每週自動：附 GitHub Actions 的週一排程和手動觸發流程；由於本地無 remote，預設分支沒有 workflow 之前不得說已在雲端啟用。可以在本機有權限時登記 Windows 每週排程，並如實說明電腦關機不會即時執行。

## 非目標
不連用戶 Codex、不遠端安裝、不用大模型產生即時提示詞、不執行任何外部 SKILL.md、不能保證抓到 GitHub 所有 Skill、候選不直接輸出安裝指令。

## 驗收
- 用「我想讓網站更美觀」或「我要測試網頁」得到有原因的推薦；不相干查詢有空結果。
- 繁簡切換能影響首頁、詳細頁、使用指南、推薦原因，且不改英文 slug、命令、來源 URL；切換後仍能用兩種字體搜尋。
- GitHub 發現流程以真實 repo 或 mock JSON 驗證候選去重、來源路徑、安全邊界、API 失敗的原子回退。
- 每週任務配置有可驗收的日期與執行方式；部署前提要記錄；測試、lint、型別與 build、桌面和手機 UI 通過。
